# 小鹤音形 · 移动端方案（iOS 仓输入法 Hamster）

## 这是什么，为什么和 Mac 版不一样

| | Mac（`flypy_xhfast`） | 手机（本方案） |
|---|---|---|
| 编码 | 双拼为主，形码按需（`derive\|/\|\|`） | **定长四码音形** |
| 治重码 | 权重 + `Ctrl+t` 置顶 / `Ctrl+j` 降频 | **编码层面就没什么重码**（66.6% 唯一） |
| 依赖 lua | 重度（`cand_selector` 等 5 个） | **完全不用** |
| 设计前提 | 盲打 → 首选正确率是唯一 KPI | 触屏 → **少选字**是唯一 KPI |

手机上没有 `Ctrl+t` 可按，也不存在盲打，所以 Mac 那套照搬过来大部分功能是空的。
反过来，音形的定长四码在触屏上价值最大 —— **触屏最贵的动作是翻候选和点选择，
四码定长把这个动作直接消掉三分之二。**

两者共用同一份 `cn_dicts/`，字集与权重一致，不会出现「Mac 上有这个字、手机上没有」。

## 取码规则

```
单字        双拼2 + 鹤形2          梦 = mg + mx
二字词      首字双拼 + 末字双拼     会籍 = hv + ji
三字词      前两字首码 + 末字双拼   输入法 = u + r + fa
四字以上    前三字首码 + 末字首码
```

全部四码。打不满四码时靠 `enable_completion` 按权重出候选，等价于简码，
但**没有发明任何固定简码** —— 免得跟你已有的肌肉记忆冲突。

## 生成词库

```bash
python3 tools/gen_mobile_yinxing.py          # 默认权重阈值 5000
python3 tools/gen_mobile_yinxing.py 2000     # 覆盖更全，但同码候选变多
```

`flypy_yinxing.dict.yaml` **不入版本控制**（2.7M 生成物），换机器重跑一次即可。

阈值 5000 的实测：

```
135,817 条（单字 9792 + 词 126,025）  2.7 MB
唯一候选 66.6%  ·  两候选 15,933 码位  ·  >8 候选仅 423 码位
```

## 导入 Hamster

1. App Store 装「仓输入法」（小鹤音形因版权不内置，必须自己导）
2. 设置 → 键盘 → 仓输入法 → **打开「完全访问」**
3. 把本目录三个文件传进去，二选一：
   - 仓输入法内「Wi-Fi 上传方案」，浏览器访问 app 显示的地址
   - 「文件」app → 我的 iPhone → Hamster → `Rime` 文件夹
4. 在 app 内「重新部署」

需要传的文件：

```
flypy_yinxing.schema.yaml
flypy_yinxing.dict.yaml     ← 先在 Mac 上生成
default.custom.yaml
```
